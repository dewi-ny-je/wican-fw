## Overview

The Datalogger records selected PID values over time and stores them in an
[InfluxDB v1](https://docs.influxdata.com/influxdb/v1/) time-series database, or
on a local SD card when no network is available. It is built for unattended,
long-running logging: data is batched in memory, optionally gzip-compressed, and
written in large chunks to minimise upload overhead and SD-card wear.

Key characteristics:

* **Per-PID frequency** – Each logged PID has its own logging frequency from
  **1 to 60 seconds**.
* **Buffered + batched** – Samples accumulate in RAM as InfluxDB *line protocol*
  and are flushed when the buffer fills or a maximum delay elapses.
* **gzip compression** – The buffer can be compressed before upload / SD write,
  increasing how much data fits per batch and reducing flash/SD wear.
* **Wi-Fi → InfluxDB over HTTPS** – When Wi-Fi is connected the batch is POSTed
  to `https://<host>/write` with TLS (public CA bundle).
* **Offline → SD card** – On WiCAN **Pro** (which has an SD slot), when Wi-Fi is
  down the batch is appended to a daily file on the SD card instead.

## Requirements

* **Protocol must be set to `AutoPID`.** The Datalogger samples the values that
  the AutoPID engine computes from the CAN bus, so the PIDs you want to log must
  first be configured under AutoPID. This design keeps a single owner of the CAN
  request queue and avoids bus contention.
* **SD logging requires WiCAN Pro.** Other hardware revisions have no SD slot;
  on those boards, batches that cannot be uploaded are retained in RAM (up to a
  configurable cap) and the oldest data is dropped if the cap is exceeded.

## Configuration

Open `http://<device-ip>/datalogger` in a browser (the device's web UI host).

| Setting | Description |
| --- | --- |
| **Enable datalogger** | Master on/off switch. |
| **Compress buffer (gzip)** | Compress each batch before upload / SD write. |
| **PIDs to log** | A list of `sensor name` + `frequency (s)`. Names must match the AutoPID sensor names; the field auto-completes from the live AutoPID values. |
| **InfluxDB Base URL** | e.g. `https://influx.example.com:8086` (no `/write`). |
| **Database / Measurement** | Target database and measurement name (default `obd`). |
| **Username / Password** | InfluxDB v1 credentials (sent as `u`/`p` query params). |
| **Skip TLS hostname check** | Relax the certificate CN check for self-hosted certificates. |
| **Flush at (bytes)** | Flush once the uncompressed buffer reaches this size. |
| **Max delay (s)** | Force a flush at least this often, even if the buffer is not full. |
| **Max buffer (bytes)** | Hard cap on retained data when offline; oldest data is dropped beyond this. |
| **Write to SD when offline** | (WiCAN Pro) append batches to the SD card while offline. |
| **SD directory** | Target directory on the card (default `/sdcard/wican`). |

Settings are applied immediately on **Save** — no reboot required.

## Data format

Each sample is one InfluxDB line-protocol record:

```
obd,device=<device-id>,sensor=<name> value=<v> <unix-seconds>
```

* The `device` tag is the WiCAN unique id; `sensor` is the AutoPID sensor name.
* Timestamps (second precision) are added once the clock is set via SNTP, which
  the Datalogger starts automatically when Wi-Fi comes up. Before the clock is
  set, records are written without a timestamp and the InfluxDB server assigns
  the receive time on upload.

### SD files

Files are named `obd-YYYYMMDD.lp` (or `obd-YYYYMMDD.lp.gz` when compression is
enabled) and new batches are appended. gzip members concatenate into a valid
gzip stream, so a `.lp.gz` file can be read directly:

```bash
gunzip -c obd-20260622.lp.gz
```

You can then import the line protocol into InfluxDB:

```bash
influx -import -path obd-20260622.lp -precision s -database wican
```
